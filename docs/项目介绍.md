# 风信 Kaze no tayori（風の便り）· 项目介绍

## 一句话介绍

风信（風の便り）是一个让陌生人的思绪匿名漂流、彼此传递的系统。在这里，信是唯一的语言。你可以将信投入漂流池，任其漂向未知远方；也可将其锚定于脚下土地，等待某位来者亲手发掘。信上不会记录你的用户名，只留下「地点 · 时间 · 天气」。这是一套「作品先于作者抵达」的慢媒介，不是社交网络，更非推荐平台。

## 项目背景

本次参赛赛道为「制造一点意外」——反「更懂你」的算法，创造用户未曾预料会遇见的事物。推荐算法总是不断推送最合我们口味的内容。生活变得便捷，却也变得越来越可预测。可偏偏那些真正让人记心上的瞬间，往往来自计划之外。风信给出的答案，是主动与算法共谋一场「意外」：它不去预测你想看什么，只是把一封陌生人的信，随机地、或者偶然地按地点，递到你的手里。它不追求精准，只负责为你打开某种新的可能。

灵感有两个起点。一个是概念上的：Yorushika 的专辑《二人称》围绕着「书信」展开，随专辑发行的书简型小说开头写道——「你面前就有一个棕色信封。你突然有冲动想读一遍。」这让我们重新去想：书信这种古老的载体，今天还能做什么？另一个是身体上的：某一个夏天，有人在太平洋边看到一种近乎透明的蓝，脑子里浮起歌词，举起手机拍下海，本能地想分享给谁，却发不出去。发朋友圈，看到的人都认识他；点赞会来，但他分不清哪个赞里是真被这片海触动，哪个只是习惯性滑过。最后，照片和歌词锁进备忘录，无人知晓那个傍晚他想起什么。手账、明信片、写信的复兴，说明这份渴望是普遍的：我们需要一种只传递内容、不传递身份的慢媒介。而如今，定位、LLM、地理数据库，已足够轻盈地承载它。

## 解决的问题

风信想解决四个非常具体的问题：

1. **身份先于内容抵达：** 在几乎所有社交平台上，你发出的第一句话，都先挂着「你是谁」。头像、昵称、粉丝数替你的话发言，大家总是先看人，再看字。
2. **点赞是失真和伪饰的：** 一个赞里，混杂着真情共鸣、顺手划过的肌肉记忆，以及对「你这个人」的追捧。它传递的是「被看见」，而不是「被理解」。
3. **私域太窄，公域太吵：** 朋友圈的受众有限且同质化，公共平台又淹没在算法和表演里，两头都装不下「此刻我真正想说的那句话」。
4. **最遗憾的事：** 两个本可相遇的陌生人，终究没能说上一句话。同乘一班夜车、同在一片海边的两个人，只因「不认识」，便终生不交换任何东西——哪怕他们可能恰好懂彼此。

风信把「你是谁」轻轻拿掉，只保留「此情此景」（地点 · 时间 · 天气）作为共鸣的锚点，好让「你想说什么」能够被纯粹地听见。我们用随机与地理两条投递路径，让陌生人之间恰到好处的相遇成为可能。

## 核心功能

**写一封信** 打开 App 即以设备登录，无需繁琐注册。写信页是一张所见即所得的信纸，支持图文混排（最多 3 张照片）与带有手写体温度的文本层。落款由定位自动填入：逆地理服务给出地名，天气服务给出此刻的气象，信尾自动落下「地点 · 日期 · 时段 · 天气」；你也可以手动修改。

寄出时有两种选择：

- 📮 **投递出去（Drift）：** 放入随机漂流池，等待任意一位陌生人抽走。
- 📍 **留在这里（Stay）：** 锚定在当前位置，埋进这片土地。

信寄出后，AI 会在后台提炼正文里的意象，写一首不超过四行的短诗附在信上，与正文同屏呈现。AI 润色与短诗功能均可完全关闭；即使服务失败也会自动降级为纯手写信，绝不影响主流程。

**收一封信** 收信有两个并列的入口：

- **随机漂流：** 抽到信件时，首先看到的是一只带有宛名与邮戳的封筒。拆封是一次性的仪式，开信后进入阅读器。读过或丢弃的信不会再出现，池空时，页面会提示「此刻还没有漂来的信」。
- **就地发掘：** 当你走到某处，应用会按定位检索附近一公里内「留在这里」的信——三年前有人埋在海边的那封信，三年后由另一个陌生人亲手翻出来。

读信时，你可以：

- ✦ **共鸣：** 一键表达，不展示身份，只记录数字（页面显示「已被 N 个陌生人接住」）。
- **抄本：** 收进个人的私密收藏夹。
- **回信：** 回以一封新的信件。回信是一封独立的作品，而非私信，它同样需要选择「留」或「投」，面向所有陌生人。原作者只会收到一句轻悄悄的通知——「你写的那封信，收到一封回信 ✦」——但这封信并不属于他个人。

**留存与表达** 除了核心的收发流程，我们还设计了一套留存体验：

- **我的信：** 随时查看寄出信件的状态，支持长按下架。
- **信件导出：** 可将信件导出为匿名长图，采用天色同源构图，方便保存或分享，绝不留存作者信息。
- **全局天色联动：** 应用背景会随「天气 × 时段」进行十二档自然渐变。读信时，背景由信件自身的落点决定——读到一封雨天深夜的信，你的整个屏幕就是那个雨夜。
- **基础保障：** 包含设置、关于页与反馈通道。所有信件发布前均经过关键词与大模型的双重审查，并设有举报入口。为了解决冷启动，应用内预置了 12 封种子信，评审打开即可抽到真实的内容。

## 技术方案

项目整体采用 monorepo 架构：`apps/app` 为 Flutter 主应用（Android 优先，已验证 iOS，Web 作为演示兜底），`services/api` 是 FastAPI 后端，`packages/natsu_no_tegami` 为 Flutter 设计系统包/组件包，`infra` 则是云端 docker-compose 部署文件。

数据层使用 PostgreSQL + PostGIS。就地发掘的核心是一条 `ST_DWithin` 地理查询：埋信时坐标以 `Geography(POINT,4326)` 写入并建立 GiST 索引；发掘时直接以米为单位检索，省去复杂的投影换算。随机漂流则基于 `ORDER BY random()` 实现纯随机抽取，结合 `letter_reads` 表实现「开封后不再现、冷却期内不复现」的去重逻辑与计数幂等自增。前端采用 Riverpod 3 + go_router + dio，按 Feature 分块组织代码。权限、定位、生命周期等基础能力由全局控制器管理，模块间禁止交叉导入，也严禁硬编码颜色字号——所有视觉风格统一定义在自研设计系统的 Token 层（包含夏日天空渐变、和纸质感与手写体温度层）。

工程实现上有三个设计决策：

1. **用类型系统约束匿名：** 匿名性不依赖“开发者记得删掉作者信息”，而是写死在类型系统里。对外响应统一使用不含作者字段的 `LetterPublic` 结构；需要作者视角的接口独立走 `/me/*` 路径，并有专门的单元测试断言“只要加入作者字段，编译或测试就会报错”。
2. **全面且保守的降级机制：** AI、天气、逆地理、对象存储（七牛云 Kodo，失败时落盘本地）均设有开关与超时降级。即便部分服务失效，主流程（写→漂→收→共鸣→再写）依然畅通。内容审核的降级方向则保持严谨——审核服务失效时，信件会停留在待审状态，绝不直接公开。
3. **把产品价值观写进代码：** 项目规范明确禁止出现点赞、关注、 Feed 流、热榜等语义的代码。列表排序只允许按照时间或随机排列，数据统计也仅限于有限的几个叙事计数。这些不是临时取舍，而是可以通过 Code Review 和自动化测试约束的底线。

在质量保障上，项目坚持契约先行（OpenAPI 契约冻结，文档与代码同步提交），全仓通过 `make check` 覆盖类型检查与测试，核心链路已在 Android 模拟器与真实后端上完成了端到端的完整验收。

## 创新点

机制创新：投递与发掘并存。「随机漂流」制造纯粹的意外；「就地发掘」让同一片土地上的陌生人得以跨越时间对话。埋信者与发掘者可能相隔三年，却立于同一片海边。我们将随机做得很彻底：没有相似度加权，没有兴趣画像，抽到什么全凭偶然，这是对推荐算法的一次温和反叛。

价值观创新：用工程手段硬性执行「反社交度量」。没有点赞、没有关注、没有热榜、没有 Feed 流。唯一的互动是只记数的共鸣与独立的回信。展示层绝不出现作者信息，回信也是漂流的新作品而非私信。在人人被量化为互动数据的时代，我们想保留共鸣最本真含义——一种「原来不止我这样」的确认，而不是谁更受欢迎的比拼。

体验创新：给数字媒介赋予物质感。拆封是一次性的仪式（读完即不可重来）；信纸带有手写体与折叠动画；信封宛名采用竖排自适应；背景天色与信件的地点、时间、天气实时联动；导出长图保持统一的构图比例。我们让「慢」不再只是一个概念，而是变成触手可及的质感。

## 应用价值

对个体，风信是一个毫无压力的真实表达出口。你可以把心里最真诚的部分交出去，而不用担心被评价、被凝视。

对旅行与在地文化，每一封信都是一枚数字时代的地理邮戳。它锚定在真实的经纬度上，随着时间沉淀，城市的角落里会埋下一层层由陌生人书写的记忆。这对文旅、城市探索以及线下空间（咖啡馆、书店、车站的「埋信点」）都具备直接的想象空间。

在社会实验层面，它是信息茧房时代的一次反向验证：当把身份、粉丝数、算法全部拿掉，陌生人之间是否依然存在真实而温暖的连接？我们的答案写在每一条「已与 N 个陌生人产生共鸣」的叙事里。匿名在这里不是逃避，而是一种温柔——它不追逐算法、不贩卖注意力、不把人变成数据，只是让一封信，找到另一个人。

当然对不同的人，在更多的场景下，风信的价值可能还有不同的阐述：你可以把它当成一个可以偶然被陌生人看到的旅行相册，也可以当作一次「圣地巡礼」的凭证等待同好者发现，又或者仅仅是一个简单好用的图文的排版工具，方便分享给朋友——尽管这和风信最核心的理念有所偏差，但我们完全支持这样的做法。

## 使用说明

风信无需注册，打开 App 即可自动完成匿名登录并进入首页。所有功能入口都收拢在首页的左侧抽屉中，最核心的操作只有两个：「写一封」与「收一封」。

- **写一封信：** 进入写信页，面前是一张所见即所得的信纸。你可以撰写正文、附上最多三张照片。确认落点时，定位服务会自动带出地名与当前天气，在信尾生成「地点 · 日期 · 时段 · 天气」的落款（地名可手动修改）。最后选择寄出方式：📮「投递出去」让信漂向不知名的陌生人；📍「留在这里」把信埋在当前位置。寄出后，系统会自动为这封信附上一首短诗。写作途中退出也不用担心，草稿会自动保存，下次打开时即可恢复。
- **收一封信：** 抽屉里有两个并列的入口。「随机漂流」会递来一只带有竖排宛名与邮戳的信封，点击即可拆封。拆封是一次性的仪式，读过之后信件便会从你的漂流池中消失。「就地发掘」需要开启定位，可以翻看附近一公里内埋下的信，按时间顺序排列，读过的不重复出现。
- **读信交互：** 在读信界面，你可以一键点击 ✦ 表达共鸣（仅记录数字，信上会留下「已与 N 个陌生人产生共鸣」）；也可以将其记入抄本随时重读；或者回以一封信（回信会重新进入写信页，同样需要选择「留」或「投」，它是一封独立的新作品而非私信）；此外还支持导出匿名长图或提交举报。
- **留存与设置：** 抽屉里的「回信」入口会提示你「你写的那封信，收到一封回信 ✦」，点击可直接查看那封公开的回信；在「我的信」中可以查看自己寄出的所有信件状态（审核中/公开/已下架），并支持长按下架；设置页提供了「天色联动」开关以及意见反馈通道。

建议先随手写一封信「投递出去」，感受寄出后它去向不明的轻盈；接着回到首页抽几次漂流信，体验拆封阅读的过程；最后如果有条件走到户外（或使用模拟器定位到有种子信的坐标，比如大连的某片海边），尝试做一次「就地发掘」——在同一个坐标上，让写信与读信的两个人，完成一次跨越时间的相遇。
